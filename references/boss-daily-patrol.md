# 每日老板巡检

给老板本人用，不给单个业务员做单客分析。命中后直接执行，不要先问看哪个客群。

## 触发词

每日客户机会巡检、老板日报、今天有哪些客户值得关注、今天全店重点客户、全店客户机会、今日重点客户、帮我检查今天最值得跟进的客户、每天帮我看哪些客户需要关注、全店客户雷达、每日客户雷达、分析今天全店客户机会、今天哪些客户需要团队重点跟进、执行今天的1688全店客户机会巡检。

这些词优先于原来的「客户机会监控」。原有交互查询保留，仅在未命中本模式时使用。

## 执行

```bash
python cli.py boss_daily_patrol
```

可选参数：`--top 10`、`--date-type RECENT_30`、`--skip-advice`、`--state-dir 目录`。

命令自动完成：

1. 拉取全部可用 AI 客群（不再只取第一个）。
2. 用原有老客筛选补充：询盘未成交、周期采购、老客促活、流失买家、高成交、高下单、B类买家。
3. 按买家账号去重，同一客户保留多个标签。
4. 只对去重后前 40 位补画像建议，失败不中断日报。
5. 排除低机会客户，输出不超过 10 位。
6. 本地有上一期快照才写变化；没有则写「当前暂无上一期可比数据」。
7. 昨天已建议联系且今天无新变化的，改为观察，避免重复骚扰。

最终回答原样输出命令返回的日报正文。禁止弹出选客群、选买家，禁止复述接口名。

## 公司业务规则

1688 没有成交，不等于业务员没跟进，也不等于客户没进展。很多询盘会转到微信、电话、WhatsApp 或线下。只能写「1688平台暂未看到成交记录，建议核实是否已转微信、电话或其他渠道继续跟进」。

当前接口没有负责人、跟进次数、回复率、微信状态、CRM 阶段。一律写「当前数据源未提供」，禁止编造姓名、完成率或「已经三天没联系」。

没有证据，不写「马上要下单」「成交概率 90%」「客户已经流失」。使用「建议重点关注」「存在复购机会」「存在流失风险」「建议核实真实进度」。

## 排序（三层，其余由模型综合）

1. 近 7 天有询盘且仍可见咨询痕迹。
2. 有询盘、平台侧暂未成交。
3. 历史采购档位高但进入沉默或流失关注；周期采购接近补货窗口；流失关注名单。

历史金额高本身不能定为高机会。没有成交信号且历史价值不高的，不进前十。

## 管理建议只允许三类

- 老板重点过问：高机会，且是重点客户、高成交档，或高价值流失风险。老板先问负责同事卡点，不直接接管客户。
- 业务员继续跟进：正常报价、复购确认、询盘核实。
- 暂时观察：信号弱，或昨天刚建议联系且今天没变化。

信息不够时写「暂无法判断是否需要老板介入」。

## 日报结构（简洁版，3-5 分钟看完）

1. 今日老板摘要：重点客户数、老板过问数、业务员跟进数、复购窗口数、流失风险数、询盘未成交数 + 一句话总结。
2. 今日最值得关注 Top 10：每位含机会等级、客户类型、为什么值得关注、当前可确认情况、管理建议、下一步动作、建议跟进时间、参考话术；询盘未成交客户附 1688 未成交提醒。
3. 需要老板重点过问的客户：客户 + 为什么 + 老板该问团队什么。
4. 今天建议业务员重点跟进：客户 + 原因 + 动作 + 话术。
5. 复购机会 / 流失风险 / 询盘未成交：各一节，无数据写「今日暂无」。
6. 相比上一期的变化：仅有真实快照时输出；无快照写「当前暂无上一期可比数据，本次不做趋势判断」。

## 快照

默认写到 `~/.openclaw/1688-customer-opportunity/patrol/latest.json`。只保存买家账号、机会等级、标签和建议跟进时间，供下一期对比。没有该文件时不做趋势判断。
